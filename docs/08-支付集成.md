# 08 支付集成

> 基于 Stripe Checkout + 支付策略工厂的多渠道支付体系 — 面向海外全球业务的支付网关

---

## 1. 支付集成是什么

本项目使用 **Stripe Checkout** 作为主要支付网关，并通过**支付策略工厂模式**（`server/utils/payment-strategies/factory.ts`）预留 PayPal、Google Pay、Apple IAP 等扩展入口。

### Supabase 内置的 Stripe 集成方案

Supabase 平台原生提供了两套 Stripe 数据集成方案，二者定位不同：

| 方案 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|----------|
| **Stripe Sync Engine** | Webhook + 定时回填，将 Stripe 数据全量同步到本地 Postgres 表（`stripe.customers`、`stripe.subscriptions` 等） | 一键安装；本地 SQL 毫秒级查询；无 Stripe API 速率限制 | 有一定同步延迟；消耗数据库存储 | 账单分析、用户消费画像、MRR/流失率统计 |
| **Stripe FDW** | Foreign Data Wrapper 扩展，实时将 SQL 查询翻译为 Stripe API 调用 | 安装简单；数据实时；不占本地存储 | 复杂查询慢（秒级甚至分钟）；受 Stripe API 限流影响 | 偶尔的简单查询或单条记录查找 |

> **本项目选择方案**：不使用 Supabase 内置方案，而是直接在服务端调用 Stripe SDK（`stripe` npm 包）。原因是本项目需要 **主动创建支付**（Checkout Session），而非仅同步账单数据做分析。Stripe Sync Engine / FDW 适合已有支付流程、需要本地分析 Stripe 数据的场景；本项目侧重点是支付流程本身。

### 本项目方案

整体架构是「创建订单 → 跳转托管支付页 → 双通道回调确认」的标准 Stripe 工作流：

- **Stripe Checkout**：托管支付页面，用户跳转至 `checkout.stripe.com` 完成支付，本项目无需处理信用卡敏感信息
- **双通道回调**：前端 `success_url` 跳转 + 服务端 Webhook 异步通知，双重保障订单状态同步
- **支付策略工厂**：`stripe / paypal / google-pay / apple-iap / manual` 五种策略，通过工厂统一创建，新增支付渠道只需添加策略实现
- **金额安全保障**：数据库 `NUMERIC(10,2)` + 服务端 `Math.round(amount * 100)` 最小单位转换，杜绝浮点数精度问题
- **审计日志**：创建订单 → 支付确认 → 退款，全链路可追溯

> 本模块通过支付策略工厂隔离了各渠道差异，服务端 `server/utils/payments.ts` 封装了 Stripe 初始化、订单号生成、签名验证等通用能力。

## 2. 前置准备

### 2.1 注册 Stripe 账号

1. 打开 [dashboard.stripe.com/register](https://dashboard.stripe.com/register)
2. 用邮箱注册，选择国家/地区
3. 完成邮箱验证后进入 Dashboard

### 2.2 获取 API 密钥

Stripe Dashboard → Developers → **API Keys**：

| 密钥 | 配置位置 | 可见性 |
|------|---------|--------|
| Publishable key（`pk_test_...`） | `payment_configs` DB 表 | 浏览器可见 |
| Secret key（`sk_test_...`） | `system_configs.payment_secrets` DB | **仅服务端** |

> 开发阶段使用 Test Mode（密钥 `sk_test_` / `pk_test_` 前缀）。上线前切换 Live Mode 并更新密钥。

### 2.3 配置 Webhook Secret（生产环境）

1. Stripe Dashboard → Developers → **Webhooks** → Add endpoint
2. Endpoint URL：`https://你的域名/api/v1/payments/webhook`
3. Events to send：选择 `checkout.session.completed` + `charge.refunded`
4. 创建后复制 **Signing secret**（`whsec_...`），配置到管理后台「业务运营 → 支付管理」→ Stripe Webhook Secret。

> Stripe 密钥已全部迁移至 DB：Secret Key + Webhook Secret → `system_configs.payment_secrets`，Publishable Key → `payment_configs`。不再通过 `.env` 环境变量配置。

> 本地开发时可使用 [Stripe CLI](https://stripe.com/docs/stripe-cli) 转发 Webhook：`stripe listen --forward-to localhost:3000/api/v1/payments/webhook`

### 2.4 备选路径：仅需 Stripe 数据同步

如果你的项目已有独立支付流程，只需要在 Supabase 数据库中分析 Stripe 账单数据（客户、订阅、发票、MRR 等），可直接使用 Supabase 的一键集成，无需写代码：

1. Supabase Dashboard → **Integrations** → 找到 **Stripe Sync Engine**
2. 输入 Stripe API 密钥（建议使用受限密钥）
3. 安装完成后数据自动同步到 `stripe.*` 表

详情参考 [Supabase Stripe Sync Engine 文档](https://supabase.com/blog/stripe-sync-engine-integration)。

### 2.5 确认用户认证已配置

支付接口要求用户已登录（非匿名），确保认证体系已就绪。参考 [07-用户认证.md](./07-用户认证.md)。

## 3. 架构概览

```
用户点击"支付"按钮
    ↓
POST /api/v1/payments/create  (创建订单 + Checkout Session)
    ↓
Stripe 托管支付页面 (checkout.stripe.com)
    ↓
用户完成支付
    ↓
┌──────────────────────────────────────────┐
│  双通道回调                                │
│  ├── GET /api/v1/payments/confirm        │  (前端 success_url 跳转)
│  └── POST /api/v1/payments/webhook       │  (Stripe 服务端异步通知)
└──────────────────────────────────────────┘
    ↓
更新 orders 表 status → paid
    ↓
审计日志记录
```

## 6. 数据库设计

### 6.1 orders 表（0002_iap.sql）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID | 主键 |
| `order_no` | TEXT (UNIQUE) | 订单号：`ORD-{timestamp}-{random}` |
| `product_id` | TEXT | 商品 ID |
| `product_name` | TEXT | 商品名称 |
| `amount` | NUMERIC(10,2) | 金额（数据库 + 服务端双重 NUMERIC 保障） |
| `currency` | TEXT | 币种：USD / EUR / ... |
| `status` | TEXT | pending → paid / failed / refunded |
| `user_id` | UUID | 关联用户（RLS 隔离） |
| `payment_provider` | TEXT | stripe / paypal / manual |
| `payment_intent_id` | TEXT | Stripe Payment Intent ID |

### 6.2 RLS 策略

- `orders_user_own`：用户可查看和创建自己的订单
- `orders_service_update`：service_role 可更新订单状态（Webhook 回调）
- `orders_admin_all`：管理员全权限

## 7. 服务端 API

### 7.1 创建支付

`POST /api/v1/payments/create`

```json
{
  "productId": "p1",
  "productName": "HEHE Pro 工具套件",
  "amount": 29.99,
  "currency": "USD"
}
```

处理流程：创建 orders → 创建 Stripe Session → 更新 payment_intent_id → 审计日志 → 返回 checkoutUrl

### 7.2 支付确认

`GET /api/v1/payments/confirm?session_id=cs_xxx`

### 7.3 Webhook 接收

`POST /api/v1/payments/webhook`

**安全验证**：必须验证 `stripe-signature` 请求头签名。

处理事件：`checkout.session.completed` → paid / `charge.refunded` → refunded

Auth 中间件白名单：`02.auth.ts` 和 `05.access-guard.ts` 均跳过此端点的 JWT 验证。

### 7.4 查询订单

`GET /api/v1/payments/[id]` / `GET /api/v1/orders`（RLS 隔离）

## 11. 金额安全

- **数据库层**：`amount NUMERIC(10, 2) NOT NULL CHECK (amount >= 0)`
- **服务端层**：`Math.round(amount * 100)` 转换为最小单位（cents）
- **严禁浮点数**：数据库 + 服务端双重保障

## 14. 常见问题

### Q: 支付成功但订单状态仍是 pending

Webhook 未正确接收 → 检查管理后台 Stripe Webhook Secret 配置 → 本地用 Stripe CLI 转发

### Q: Webhook 签名验证失败

Secret 复制不完整 / 请求体被中间件提前解析 / Vercel Function 对 body 做预处理

### Q: 金额显示不正确

Stripe 要求最小单位（分），确认传入金额是 `number` 类型
