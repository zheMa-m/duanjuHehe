## 一、概述与核心问题

SSR、ISR、SWR 三种渲染模式是现代全栈框架（Nuxt 4 / Next.js）的核心能力。三者本质上都是「服务端介入渲染」，核心差异在于：

- **何时渲染**：每次请求实时渲染 vs. 首次构建后缓存
- **缓存多久**：无缓存 vs. 固定 TTL vs. 协商过期
- **谁触发更新**：用户请求 vs. 后台定时任务 vs. 按需 Webhook

选错渲染策略，轻则 LCP 超标被 CI 打回，重则服务器在流量峰值下崩溃。本文给出可落地的决策框架。

## 二、核心机制全维度对比

| 对比维度 | SSR（服务端渲染） | ISR（增量静态再生） | SWR（协商缓存渲染） |
|----------|-------------------|---------------------|---------------------|
| 全称 | Server-Side Rendering | Incremental Static Regeneration | Stale-While-Revalidate |
| 渲染时机 | 每次请求实时渲染 | 首次请求渲染并缓存，后台定时刷新 | 缓存过期后立即返回旧缓存，同时后台异步刷新 |
| TTFB 首字节 | 慢（200-800ms，每次） | 极快（命中缓存时 ~5ms） | 快（缓存期内 ~5ms） |
| 数据新鲜度 | 100% 实时 | 最多延迟 revalidate 秒 | 最多延迟 maxAge+revalidate 秒 |
| 服务器压力 | 高（每请求计算一次） | 极低（缓存期零计算） | 低（过期后异步一次） |
| SEO 友好度 | 极佳（实时 HTML） | 极佳（静态 HTML） | 极佳（静态 HTML） |
| 适合更新频率 | 秒级（实时变化数据） | 小时/天级（几乎不变内容） | 分钟/小时级（中频更新内容） |
| 流量峰值表现 | 服务器随流量线性增压 | 边缘节点承压，服务器零压力 | 边缘承压，服务器极低压力 |
| Nuxt 4 配置 | `routeRules: { ssr: true }` | `routeRules: { isr: 3600 }` | `routeRules: { swr: 600 }` |

## 三、机制原理图解

以下伪时序图展示三种策略在「用户请求 → 返回响应」链路上的行为差异：

### 3.1 SSR — 每请求实时计算

```
用户请求
   │
   ▼
[服务器] ── 查 DB / 调 API ──▶ 渲染 HTML ──▶ 返回给用户
   │
（下次请求重复上述流程，服务器每次都要计算）
```

### 3.2 ISR — 首次构建 + 后台静默刷新

```
首次请求
   │
   ▼
[服务器] ── 计算 ──▶ 返回 HTML + 写入边缘缓存（TTL=3600s）

3600s 内后续请求
   │
   ▼
[边缘缓存] ──▶ 直接返回（~5ms，服务器零压力）

缓存过期后首个请求
   ▼
[返回旧缓存] + [后台触发服务器重新计算，更新缓存]
（用户无感知，永远不等待）
```

### 3.3 SWR — 过期即用旧缓存 + 后台异步更新

```
首次请求
   │
   ▼
[服务器] ── 计算 ──▶ 返回 HTML + 写入缓存（maxAge=600s）

600s 内
   ▼
[缓存命中] ──▶ ~5ms 返回

600s 后（缓存 Stale 状态）
   ▼
[立即返回旧缓存（fast）] + [后台异步刷新]
下一次请求 ──▶ 拿到最新缓存
```

> 💡 **关键结论**：ISR 和 SWR 在「过期后先返回旧缓存、后台异步刷新」这一行为上几乎完全一致。核心区别是时间窗口语义：ISR 适合小时/天级，SWR 适合分钟级。

## 四、真实性能数字参考

| 场景 | SSR TTFB | ISR TTFB | SWR TTFB |
|------|----------|----------|----------|
| 冷启动（无缓存） | 200-800ms | 200-800ms | 200-800ms |
| 热请求（有缓存） | 200-800ms（每次重算） | ~5ms（命中缓存） | ~5ms（命中缓存） |
| 流量峰值（10x） | 服务器 CPU 飙升，可能 OOM | 边缘承压，服务器零增压 | 边缘承压，服务器极低增压 |
| 数据最大延迟 | 0（实时） | 最长 revalidate 秒 | 最长 maxAge + stale 秒 |

## 五、选型决策树

以下两个维度组合使用，即可快速确定渲染策略：

### 5.1 维度一：数据更新频率

```
数据多久变化一次？
│
├── 秒级变化（股价、实时弹幕、直播数据）
│   └── SSR（或客户端轮询 / WebSocket）
│
├── 分钟到小时级（营销活动、商品库存、新闻）
│   └── SWR（允许用户看到「几分钟前」的数据）
│
└── 小时到天级（官网介绍、博客、定价页）
    └── ISR（内容几乎不变，追求极致性能）
```

### 5.2 维度二：SEO 重要性

```
这个页面对 SEO 重要吗？
│
├── 不重要（管理后台、用户私有页、订单详情）
│   └── SPA（ssr: false）完全客户端渲染
│
└── 重要（官网、博客、营销落地页）
    └── 按「数据更新频率」三选一（ISR / SWR / SSR）
```

## 六、本项目各页面选型定论

结合「单人全栈单仓混合技术架构方案 v1.0」，各类页面渲染策略最终决策如下：

| 页面 / 场景 | 选型 | Nuxt 4 配置 | 选择理由 |
|-------------|------|-------------|----------|
| 官网首页 / 定价页 / 博客列表 | ISR | `isr: 3600` | CMS 驱动，每日更新一次已足够。极致 LCP，SEO 100 分。 |
| 营销 H5 活动页 | SWR | `swr: 600` | 活动配置随时可改，容忍 10 分钟延迟，不能每次都慢。 |
| 博客详情 / 静态文章页 | ISR | `isr: 86400` | 内容发布后极少修改，24 小时缓存完全够用。 |
| 用户个人中心 / 订单页 | SSR | `ssr: true` | 与登录用户强绑定，必须实时，绝对不可缓存。 |
| 管理后台全部页面 | SPA | `ssr: false` | 无 SEO 需求，强权限隔离，实时交互，禁止 SSR。 |
| API 接口（/api/v1/*） | 无渲染 | `no-store` | 纯 JSON，绝对禁止任何缓存，每次实时计算。 |
| 搜索结果 / 用户生成内容 | SSR | `ssr: true` | 内容完全动态，因人而异，不可静态缓存。 |

## 七、常见误区 Q&A

### Q1：ISR 缓存过期，用户会看到空白页或加载等待吗？

**不会。** ISR 过期后，第一个到来的请求依然立即拿到旧缓存（用户无感知），服务器在后台静默刷新完成后，下一个请求才会拿到最新内容。用户永远不需要等待，这是 ISR 相比 SSR 最大的优势。

### Q2：ISR 和 SWR 本质区别是什么？

**核心差异在语义与时间窗口，不在机制。** 两者在「过期后先返回旧缓存、后台异步刷新」这一行为上几乎完全一致。区别：ISR 定位于「小时/天级低频更新的静态内容」；SWR 定位于「分钟级中频更新的动态内容」，允许更短的 maxAge。

### Q3：SSR 在什么情况下是唯一正确选择？

**三种情况必须用 SSR：** 1. 页面内容因用户身份不同而完全不同（个人中心、订单、私信）；2. 内容必须是秒级实时数据（行情、实时库存、竞拍倒计时）；3. 页面含高度敏感数据，不允许任何缓存（金融账户、医疗记录）。

## 八、Nuxt 4 routeRules 配置速查

在 `nuxt.config.ts` 中通过 `routeRules` 统一配置各路由的渲染策略：

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  routeRules: {
    // 官网：ISR，1 小时刷新
    '/client/**': { isr: 3600 },

    // 营销 H5：SWR，10 分钟刷新
    '/h5/**': { swr: 600 },

    // 管理后台：SPA，禁止 SSR
    '/admin/**': { ssr: false, headers: { 'cache-control': 'no-store, private' } },

    // API 引擎：纯接口，禁止缓存
    '/api/**': { cors: true, headers: { 'cache-control': 'no-store' } },

    // 用户个人中心：SSR，实时渲染
    '/dashboard/**': { ssr: true, headers: { 'cache-control': 'no-store, private' } },
  }
})
```

| 策略 | 一句话定位 | 记忆口诀 |
|------|-----------|----------|
| SSR | 实时性第一，牺牲性能 | 每次都做饭，新鲜但慢 |
| ISR | 性能第一，内容几乎不变 | 做好放冰箱，定时换新 |
| SWR | 性能与时效的最佳平衡 | 过期先凑合，后台悄悄换 |
